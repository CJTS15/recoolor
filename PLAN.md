# Pinta plan

Working plan for Pinta, a GNOME theme switcher in Rust. Tick boxes as you go.
The code layout described here matches `main` after PR #1.

## Goal

A libadwaita app where you pick a palette (Catppuccin, Dracula, Tokyo Night, …)
and it recolors everything you see on a GNOME desktop:

- GTK4/libadwaita and GTK3 apps (done in step 1, via generated `gtk.css`)
- Flatpak apps
- GNOME Shell (top bar, quick settings, overview)
- Icon and cursor themes

Personal use first. Bundled palettes and generated CSS come first; installing
upstream themes is the last step.

## Ground rules

- `pinta-core` never depends on GTK. Anything that touches files, gsettings
  keys as data, or CSS lives there and is unit-tested with temp dirs.
  GTK/GIO calls live in the `pinta` crate.
- Never overwrite or delete something Pinta did not write. Every target gets
  the same treatment as `gtk.css`: a marker to recognise Pinta's own output,
  a backup of whatever was there, and a restore that undoes exactly that.
- Everything Pinta changes must be undoable from one Reset button (and
  `pinta restore`).
- `cargo test` and `cargo clippy --all-targets -- -D warnings` stay clean on
  every commit.

## Step 2: GUI

A libadwaita window with a palette grid and live previews, Apply and Reset,
and light/dark awareness through GNOME's `color-scheme`.

### 2.1 Dependencies and app shell

- [ ] Install system dev packages: `libgtk-4-dev libadwaita-1-dev` (Debian/Ubuntu)
      or `gtk4-devel libadwaita-devel` (Fedora).
- [ ] Add to `crates/pinta/Cargo.toml`, using the newest releases on crates.io:
      `gtk = { package = "gtk4", features = ["v4_16"] }` and
      `adw = { package = "libadwaita", features = ["v1_6"] }`.
      Raise the feature levels only if you need newer APIs; they set the
      minimum GNOME version Pinta runs on.
- [ ] Pick an app ID, e.g. `io.github.cjts15.Pinta`. Note that the paint
      program Pinta already uses `com.github.PintaProject.Pinta`, so keep the
      ID distinct, and consider whether the display name could confuse.
- [ ] Split `main.rs`: move the current CLI into `src/cli.rs` unchanged.
      `pinta` with no arguments opens the window; `pinta <command>` runs the CLI.
      Call `app.run_with_args::<&str>(&[])` so GTK does not try to parse the CLI
      arguments.
- [ ] Module layout:
      ```
      crates/pinta/src/
        main.rs          dispatch: CLI or GUI
        cli.rs           today's commands
        ui/mod.rs        adw::Application setup, actions, accelerators
        ui/window.rs     main window
        ui/palette_card.rs
        ui/preview.rs
      ```
      Build widgets in code first. Move to Blueprint/`.ui` templates only if the
      window grows enough that code gets hard to read.

### 2.2 Main window

- [ ] `adw::ApplicationWindow` with `adw::ToolbarView`, an `adw::HeaderBar`,
      and an `adw::ToastOverlay` around the content.
- [ ] Palette grid: `gtk::FlowBox` (9 palettes does not need a `GridView`)
      grouped by `palette.family`, one card per palette.
- [ ] Palette card (`palette_card.rs`): name, a row of swatches
      (base, surface, text, accent, red, yellow, green, blue), and a check mark
      on the applied palette. Draw swatches with `gtk::DrawingArea` and cairo
      so cards need no per-card CSS.
- [ ] Status line at the top from `GtkConfig::status()`: "Applied: Dracula",
      "Not applied", or a warning when `gtk.css` is foreign or a backup is kept.
- [ ] Show `catalog()` errors (broken user palettes) as a banner, not a crash.
- [ ] Empty/edge states: no config home, unreadable user palettes dir.

### 2.3 Live preview

The cheap and accurate preview is Pinta's own window: libadwaita draws from
the same named colors the generated CSS sets.

- [ ] On selecting a card, load `Toolkit::Gtk4.render(&palette)` into a
      `gtk::CssProvider` and add it to the display with
      `gtk::style_context_add_provider_for_display` at
      `STYLE_PROVIDER_PRIORITY_USER`. Swap the provider's contents on each
      selection; remove it on Reset or when the selection is cleared.
- [ ] A preview pane (`preview.rs`) with sample widgets so the palette is
      visible beyond the grid: a list row, an entry, a switch, a suggested and
      a destructive button, a progress bar, a card.
- [ ] Optional: a GTK3 hint ("GTK3 apps get partial coverage") rather than a
      fake GTK3 render.

### 2.4 Apply and Reset

- [ ] Apply button (suggested style): `GtkConfig::apply`, then a toast
      "Applied Dracula. Restart apps to see it."
- [ ] `ApplyError::BackupExists`: show an `adw::AlertDialog` naming both paths
      and explaining what to move; never offer to delete.
- [ ] Reset button: `GtkConfig::restore()`, summarise the outcomes in a toast,
      clear the preview provider.
- [ ] Refresh status and the check mark after each action.
- [ ] File operations are small and fast; run them on the main thread. Move
      them to `gio::spawn_blocking` only if a later step adds slow work.

### 2.5 Light/dark awareness

GNOME's preference is `org.gnome.desktop.interface color-scheme`
(`default`, `prefer-dark`, `prefer-light`). `adw::StyleManager::dark()`
reflects it.

- [ ] In the GUI, follow `adw::StyleManager` and connect to `notify::dark`.
      Filter or sort the grid so palettes matching the current variant come
      first, with a toggle to show all.
- [ ] Let the user pick a palette pair: one light, one dark (for example
      Catppuccin Latte + Mocha). Store it in `$XDG_CONFIG_HOME/pinta/config.toml`
      (new `pinta-core/src/config.rs`, serde + toml, atomic write like `apply.rs`).
- [ ] In `pinta-core`, add a GTK4 render for a pair that wraps the dark palette
      in `@media (prefers-color-scheme: dark) { … }` (supported since GTK 4.16).
      libadwaita apps then follow the system switch live, with no Pinta process
      running. Keep the header marker format so `applied_palette_id` still works
      (e.g. `palette=catppuccin-latte+catppuccin-mocha`), and extend
      `CssState`/tests accordingly.
- [ ] GTK3 has no media query, so its `gtk.css` must be rewritten on each
      switch. Add `pinta watch`: watches `color-scheme` via `gio::Settings` and
      re-applies the GTK3 file. Ship it as a systemd user service
      (`~/.config/systemd/user/pinta-watch.service`) that the GUI can turn on.
- [ ] Optional: set `org.gnome.desktop.interface accent-color` (GNOME 47+) to
      the named accent nearest the palette's accent, saved for Reset.

### 2.6 Desktop integration

- [ ] `data/io.github.cjts15.Pinta.desktop`, `.metainfo.xml`, and a symbolic +
      scalable icon.
- [ ] A short install recipe in the README: `cargo install --path crates/pinta`
      plus copying the desktop file and icon under `~/.local/share`.
- [ ] Don't ship Pinta itself as a Flatpak yet: it writes host config files and
      gsettings, which would need broad sandbox holes.

### 2.7 Tests and CI

- [ ] Core: tests for the light/dark pair CSS, the config file, and marker
      parsing for pairs.
- [ ] GitHub Actions workflow: `cargo fmt --check`, `cargo clippy`, `cargo test`
      on Ubuntu with the GTK/libadwaita dev packages installed.

**Done when:** `pinta` opens a window, selecting a card recolors the window,
Apply writes both stylesheets, Reset brings back the previous state, and a
light/dark pair follows the GNOME switch in libadwaita apps.

## Step 3: Flatpak, GNOME Shell, icons and cursors

Each target becomes a module in `pinta-core` with the same shape as
`apply.rs`: `status()`, `apply()`, `restore()`, backups, and tests on temp
dirs. Then a section in the GUI ("Apps", "Shell", "Icons & cursors") with a
switch per target, and Reset covering all of them.

- [ ] Refactor first: introduce a small `Target` trait (or an enum) so the GUI
      and CLI iterate targets instead of hard-coding GTK. Keep it simple; four
      targets do not need plugins.
- [ ] Record what Pinta changed in `$XDG_STATE_HOME/pinta/state.toml` (add
      `state_home()` to `paths.rs`), so Reset knows the previous gsettings
      values and overrides to remove.

### 3.1 Flatpak apps

Sandboxed apps cannot see `~/.config/gtk-4.0` and `~/.config/gtk-3.0` by default.

- [ ] Grant read-only access with a user override:
      `flatpak override --user --filesystem=xdg-config/gtk-4.0:ro --filesystem=xdg-config/gtk-3.0:ro`.
      Use the `flatpak` CLI to add them.
- [ ] Before adding, read the current global override (`flatpak override --user --show`)
      and record in the state file only the entries Pinta added.
- [ ] Reset must remove exactly those entries. `--nofilesystem=` adds a deny
      rather than removing a grant, and `--reset` wipes the user's own
      overrides, so edit Pinta's entries out of
      `~/.local/share/flatpak/overrides/global` with `glib::KeyFile`. Cover this
      with a test on a sample keyfile that also holds user entries.
- [ ] Verify with a GTK4 Flatpak (e.g. Text Editor) and a GTK3 one; record which
      work in the README.
- [ ] Skip quietly with a note in the GUI when `flatpak` is not installed.

### 3.2 GNOME Shell

Requires the User Themes extension
(`user-theme@gnome-shell-extensions.gcampax.github.com`).

- [ ] New `pinta-core/src/css/shell.rs`: generate `gnome-shell.css` from a
      palette. Start from overrides of the default theme rather than a full
      theme: panel, popup menus, quick settings tiles, calendar/notifications,
      overview search, OSD, dash. Try importing the default stylesheet
      (`@import url("resource:///org/gnome/shell/theme/gnome-shell.css");`) and
      overriding colors on top; confirm it works on your Shell version.
- [ ] Write it to `~/.local/share/themes/Pinta/gnome-shell/gnome-shell.css`
      with the Pinta marker. One theme folder, rewritten per palette, keeps
      the user's themes list clean.
- [ ] Detect the extension (`gnome-extensions info`, or the Shell D-Bus
      `org.gnome.Shell.Extensions`) and explain how to enable it if missing.
- [ ] Set `org.gnome.shell.extensions.user-theme name` to `Pinta`; save the old
      value for Reset.
- [ ] Shell CSS changes between releases. Note which GNOME Shell version you
      tested and check it again after each GNOME upgrade.

### 3.3 Icons and cursors

- [ ] List installed themes from `~/.local/share/icons`, `~/.icons`, and
      `$XDG_DATA_DIRS/icons`: a folder with `index.theme` is an icon theme; one
      with a `cursors/` subfolder is a cursor theme. Pure function in core,
      tested on a temp tree.
- [ ] Set `org.gnome.desktop.interface icon-theme` and `cursor-theme` through
      `gio::Settings`; save previous values for Reset.
- [ ] Optional per-palette suggestions in the palette TOML
      (`[suggest] icons = "Papirus-Dark"`, `cursors = "..."`), used only if
      installed.
- [ ] Flatpak apps use the host icon theme only if it is installed as a
      Flatpak extension or exposed; document the limitation rather than
      solving it here.

**Done when:** one Apply recolors GTK apps, Flatpak apps and the Shell, and
sets icons/cursors; one Reset puts every one of them back.

## Step 4: Upstream theme installer

For people who want the official themes (full GTK3 coverage, Shell themes
made by their authors) instead of generated CSS.

- [ ] A sources manifest in core (`themes/sources.toml`): name, palette id it
      matches, download URL pinned to a release, `sha256`, and what the
      archive contains (gtk-3.0, gtk-4.0, gnome-shell, icons, cursors).
      Check each upstream's status first; some GTK themes are archived or
      unmaintained.
- [ ] Downloader in the `pinta` crate: `ureq` (small, blocking) on
      `gio::spawn_blocking`, checksum verified before extracting.
- [ ] Extract into a temp dir, reject absolute paths and `..` entries (path
      traversal), then move into `~/.local/share/themes/<name>` and
      `~/.local/share/icons/<name>`. Record installed folders in the state file.
- [ ] Activate: GTK3 via `org.gnome.desktop.interface gtk-theme`; GTK4 by
      linking the theme's `gtk-4.0` files into `~/.config/gtk-4.0` with the same
      backup rules as `apply.rs`; Shell via the user-theme key.
- [ ] Uninstall removes only folders Pinta recorded.
- [ ] GUI: an "Install official theme" action on cards that have a source,
      with progress and a cancel button.
